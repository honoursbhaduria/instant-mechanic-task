You need to build an AI Car Mechanic Chatbot full-stack app within 48 hours. The task is very doable if you keep the architecture simple and avoid using Gemini for things traditional backend logic can handle.
Full_Stack_Developer_Intern_Task.pdf
What you have to build

Deploy it on Vercel.
Your UI needs:

Text messages

3. Most important part: chatbot logic
Don't make Gemini handle everything.
The requirement specifically says to minimize AI/API usage and use traditional backend logic whenever possible. Full_Stack_Developer_Intern_Task.pdf
A good flow is:
User
 ↓
Chat UI
 ↓
POST /api/chat/
 ↓
Backend validates query
 ↓
Is this car/mechanical related?
 ├── NO → reject politely
 │
 └── YES
       ↓
Check required information
       ↓
Missing information?
 ├── YES → ask follow-up question
 │
 └── NO
       ↓
Diagnosis
       ↓
Gemini only when reasoning is actually needed
       ↓
Diagnosis + recommended repair
       ↓
Book Mechanic
The bot must behave like a senior automobile technician, reject unrelated questions, ask follow-ups, analyze media when useful, and recommend a repair/service. Full_Stack_Developer_Intern_Task.pdf

5. API design
Chat
POST /api/chat/
Request:
{
  "conversation_id": 1,
  "message": "My car is making a clicking noise when I turn."
}
Response:
{
  "reply": "When do you notice the clicking noise — only while turning at low speed, or also at higher speeds?",
  "conversation_id": 1,
  "needs_more_info": true
}
Upload
POST /api/upload/
Accept:
image
audio
video
Return something like:
{
  "id": 12,
  "file_url": "...",
  "media_type": "image"
}
Diagnosis
POST /api/diagnosis/
Example:
{
  "conversation_id": 1
}
Response:
{
  "diagnosis": "Possible CV joint issue",
  "severity": "medium",
  "recommendation": "Have the CV joint and axle inspected.",
  "service": "CV Joint Inspection"
}
Booking
POST /api/booking/
Example:
{
  "diagnosis_id": 1,
  "customer_name": "Honours",
  "phone": "XXXXXXXXXX",
  "vehicle": "Hyundai Creta",
  "preferred_date": "2026-09-25",
  "preferred_time": "11:00",
  "service": "CV Joint Inspection"
}
Booking details
GET /api/booking/1/
6. Gemini usage
Use Gemini primarily for:
Diagnosis
Give it structured information:
Vehicle:
Hyundai Creta 2022

Symptoms:
Clicking noise while turning left.

Conditions:
Low speed.
Only when steering.

Previous repairs:
None.

Media:
[uploaded image/audio if relevant]
Ask Gemini to return structured JSON:
{
  "possible_issue": "...",
  "reasoning": "...",
  "severity": "low|medium|high",
  "recommended_service": "...",
  "safety_warning": "..."
}
Don't call Gemini for:
saving messages
creating conversations
creating bookings
validating phone numbers
checking required fields
storing uploads
retrieving history
Those should be normal Django logic.
This directly addresses the evaluation criterion about minimizing unnecessary AI usage. Full_Stack_Developer_Intern_Task.pdf

9. Error handling
This will matter in evaluation.
Handle:
400 → Invalid request
404 → Booking/conversation not found
413 → File too large
415 → Unsupported media type
429 → Gemini/API rate limit
500 → Internal server error
Frontend should show proper messages instead of crashing.
Example:
⚠️ Something went wrong.
Please try again.
